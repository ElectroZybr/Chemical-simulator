# Баги upstream, найденные при слиянии

Эти дефекты живут в коде upstream/main (или в сторонней `wgpu_native`), а не в форк-правках.
Форк их обошёл/смягчил (см. «обход» у каждого), но первопричину стоит чинить в upstream.
Найдены при проверке слияния перед закрытием (ветка `merge-upstream`).

Термины: *short-range Coulomb* — кулон в пределах радиуса обрезки (cutoff), считается в
pair-loop по списку соседей. *long-range Coulomb (octree / Барнс-Хат)* — кулон на полном
диапазоне через дерево: ближние пары прямой суммой, дальние — мультиполем. *swapchain* —
цепочка буферов кадра, куда видеокарта рисует и откуда показывает на экран.

## 1. ForceField: при выключенном Coulomb всё равно считается фантомный Coulomb
`Lattice/Engine/physics/ForceField.cpp`, `computePairInteractions`. Диспетчер: `if LJ&&Coulomb`
/ `else if LJ` / `else`. Последняя `else` гонит ветку `<UseCoulomb=true>` НЕ проверяя
`isCoulombEnabled()`. При выключенных обоих (LJ и Coulomb) к заряженным атомам всё равно
прикладывается кулон. GPU-путь правильно молчит (`if(coulombEnabled_)`) → CPU и GPU расходятся.
**Обход:** заменили `else` на `else if(isCoulombEnabled() && !isCoulombLongRangeEnabled())`.
**Чинить upstream:** последняя ветка должна проверять `isCoulombEnabled()`.

## 2. Octree дважды считает ближний Coulomb (нет взаимоисключения)
`Lattice/Engine/physics/ForceFields/CoulombForceField.cpp`, `computeForce`. Octree считает
ПОЛНЫЙ кулон (лист — прямая сумма всех ближних пар, дальние — мультиполь), а short-range pass
работает независимо (`isCoulombEnabled`, дефолт true). Флаги ортогональны, гарда нет → при
обоих включённых ближние пары учитываются ДВАЖДЫ. **Обход:** short-range Coulomb в pair-loop
считаем только при выключенном long-range. **Чинить upstream:** либо octree исключает пары
внутри cutoff (только дальнее поле), либо включение long-range отключает short-range pass.

## 3. App-дефолт long-range противоречит безопасному дефолту движка
`App/UserSettings.h`: `simulationCoulombLongRangeEnabled = true`, тогда как движок
(`World::longRangeForcesEnabled`) дефолтит `false` (octree-аппроксимация Барнса-Хата не
сохраняет импульс). `Application.cpp` безусловно пушит App-настройку в мир на старте → на
свежей установке long-range ВКЛЮЧЁН, и любая заряженная сцена идёт с несохранением импульса.
**Обход:** App-дефолт = `false` (как движковый). **Чинить upstream:** дефолт App-настройки
не должен противоречить безопасному дефолту движка.

## 4. AtomSort: карта old→new пишется в двух разных индекс-пространствах → ремап связей врёт
`Lattice/Engine/physics/Atom/AtomSort.cpp`. `mortonOrder` строит `oldToNew_[oldPos]=newPos`
(position-индексировано, как ждёт `World::remapAtomIndices` для связей), а
`applyViewToStorage` затем перезаписывает `oldToNew_[atomId]=newPos` (id-индексировано). При
`atomId == position` (свежая сцена) совпадает; после `addAtom/removeAtom/setFixed`, меняющих
соответствие id↔позиция, id-записи затирают позиционную карту → связи ремапятся на чужие
индексы. **Обход:** убрали id-индексированную запись (mortonOrder уже строит правильную).
**Чинить upstream:** `applyViewToStorage` не должен трогать `oldToNew_`.

## 5. Octree молча полагается на Morton-порядок, не проверяя его
`Lattice/Engine/NeighborSearch/BarnesHut/Octree.cpp`, `buildNode`. Делит атомы на октанты,
полагая, что Morton-сортировка уже сгруппировала их подряд по октантам — без проверки. Если
атомы НЕ отсортированы (например сортировку отключили ради перфа на большой сцене), каждый узел
получает не те атомы → молча неверные заряды/силы, без краша и предупреждения. **Обход:**
форк-гейт Morton-сортировки принудительно сортирует при включённом long-range. **Чинить
upstream:** octree должен сам владеть/проверять порядок, а не зависеть от внешней оптимизации.

## 6. Парсер переводов молча выбрасывает строки с лишним разделителем
`cmake/generate_translations.cmake`. Регексп ждёт ровно 3 поля через `;`; строка с `;` ВНУТРИ
значения не матчится и молча `continue`-ится — перевод тихо исчезает, UI показывает сырой ключ
(так было с `imgui_gpu_physics_lj_only`). **Обход:** добавили `message(WARNING)` на пропуске;
поправили данные. **Чинить upstream:** предупреждать о пропуске или поддержать `;` в последнем
поле.

## 7. Тумблер long-range инертен в GPU-режиме, без обратной связи
GPU-путь не считает long-range Coulomb (`World.h` комментарий), но UI-чекбокс остаётся
кликабельным и сохраняется — галка без эффекта. **Обход:** дизейблим чекбокс в GPU-режиме.
**Чинить upstream:** гасить/прятать контрол, когда он не действует.

## 8. Хардкод английских строк в локализованной панели
`App/GUI/interface/panels/settings/SettingsPanel.cpp`: ползунок «Interface scale», заголовок
«Interface», драги «Size X/Y/Z» — литералы, в отличие от остальных лейблов через `_tr`.
В русском UI видны по-английски. **Обход:** перевели через `_tr` + ключи в translate.csv.
(Остаются непереведёнными и другие ключи — «Cutoff NL», «Skin NL», «Time step (Dt)» и пр.: у
них в translate.csv английский в русской колонке — отдельная задача полноты перевода.)

## 9. wgpu_native падает при принудительной смене Z-порядка окна (нужно воспроизведение)
`wgpu_native.dll` (сторонняя бинарная либа WebGPU) однажды упал с
`STATUS_STACK_BUFFER_OVERRUN` при `SetWindowPos(HWND_TOPMOST)` (смена Z-порядка). Наш обработчик
ресайза (`WGPUContext::resize`) защищён гардом размера и на смену Z-порядка вообще не зовётся,
так что это не форк-код; swapchain/surface-код — upstream-овский (`Rendering/backend/
WGPUContext.h`). Обычное использование (без принудительного topmost) не падает. **Статус:**
сторонняя либа, чинить нечем; стоит проверить, не падает ли при реальном maximize/смене монитора
(пока не воспроизведено).
